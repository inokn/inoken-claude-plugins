# php-upgrade — PHP を脆弱性の修正版へ上げるための点検

手元に持ってきたサイトのフォルダで Claude Code に頼むと、

1. 移行先の PHP（今の版から一番近い修正版）を決め
2. そのまま動くかを点検して判定（A〜D）を付け
3. 自作のコードを直し
4. **アップロードするファイルの一覧・元に戻すためのファイル・作業票・一覧表に貼る1行**

を出します。**サーバーには一切接続しません。** アップロードと PHP の切り替えは、作業票を見ながら人が行います。

| 今の PHP | 移行先 |
|---|---|
| 7.x / 8.0 / 8.1 | 8.2.35（コードの点検あり） |
| 8.2.x | 8.2.35（パッチ更新のみ。点検なし） |
| 8.3.x / 8.4.x / 8.5.x | 8.3.36 / 8.4.27 / 8.5.12（パッチ更新のみ） |

⚠️ 8.2 は 2026-12-31 でセキュリティ修正が終わります。8.2 への移行は応急処置で、次は 8.3 以上を計画してください。

## はじめに（PC ごとに1回）

Claude Code で「**php-upgrade の環境チェックをして**」と頼みます。足りないものがあれば入れ方を案内します。

- 必要なもの: Git（Claude Code に付属）、Python 3、PHP（7.4 以上。点検ツールを動かすためのもので、移行先の版と同じでなくてよい）
- Windows で PHP が無い場合: `winget install PHP.PHP.8.4` → Claude Code を再起動
- 点検ツール（phpcs + PHPCompatibility）は、初回に自動で `~/.cache/inoken-php-upgrade` に入ります（インターネット接続が必要）

## 1サイトの進め方

1. **作業フォルダを作る**: FTP ソフトで、サイトのフォルダを丸ごとダウンロードする
   - 置き場所は **OneDrive / Dropbox / Google ドライブなどの同期フォルダの外**（例: `C:\php-upgrade\サイト名\`）。お客様のコードと設定が入るため
   - `wp-content/uploads`（画像）は無くても点検できます。容量が大きければ除いて構いません
   - `wp-config.php` があっても AI は開きません
2. **そのフォルダで Claude Code を起動**して、こう頼む:

   > このサイトのPHP移行チェックをして。今のPHPは 8.0.30

3. Claude が、判定・やること・質問（「このプラグインは自作ですか、有料ですか」など）を返します。答えると修正まで進みます
4. 終わると `.php-upgrade/` フォルダに次ができます

| ファイル | 中身 |
|---|---|
| `作業票.md` | 検証環境 → 本番 → 問題が出たときの戻し方 のチェックリスト |
| `アップロード一覧.txt` | アップロードするファイル |
| `元ファイル/` | 修正前のファイル（戻すときに上げ直す） |
| `report.md` | 点検結果の詳細 |
| `一覧表用.tsv` | 棚卸し表の右側に貼る1行 |

5. 作業票どおりに、**検証環境で確認してから**本番へ

`.php-upgrade/` と `.git/` はサーバーに上げないでください（作業用の記録です）。

## 一覧表に貼る1行

棚卸し表の「備考」の右に、次の6列を足しておくと、`一覧表用.tsv` の中身をそのまま貼れます。

| 点検日 | 移行先PHP | 判定 | 要修正箇所 | 要更新プラグイン数 | 主な作業 |
|---|---|---|---|---|---|

判定: **A** そのままで可 / **B** 更新で対応 / **C** コードの修正が必要 / **D** 作り直しを検討（人が判断）

## 念のための設定（任意）

AI への指示とスクリプトの両方で「サーバーに接続しない」「認証情報を読まない」を守っていますが、保険として Claude Code の設定でも禁止できます。
`~/.claude/settings.json`（Windows は `C:\Users\<名前>\.claude\settings.json`）の `permissions.deny` に足します。

```json
{
  "permissions": {
    "deny": [
      "Read(**/wp-config.php)",
      "Read(**/.env)",
      "Bash(ftp:*)",
      "Bash(sftp:*)",
      "Bash(winscp.com:*)"
    ]
  }
}
```

AI に検証環境へのアップロードを任せる運用（rclone など）を別に使っている場合は、その運用に合わせて調整してください。

## わからないこと・限界

- コードを読んで調べる点検です。**DB・メール送信・外部サービスとの連携の不具合は、動かしてみないと分かりません。** 検証環境での確認は必ず行ってください
- 点検ツール PHPCompatibility 10 は alpha 版です。見落としや誤検知がありえます
- 有料プラグイン・有料テーマは手で直さず、販売元の最新版に更新してください
